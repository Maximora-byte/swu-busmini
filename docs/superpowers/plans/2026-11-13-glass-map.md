# Glass Map Home Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One map-first glass home replaces large tabs with search, map tools and a smooth three-position sheet.

**Architecture:** Pure layout/padding math plus a render-thread WXS gesture module; page handlers own only settled UI state and existing route planning. Existing current-data map and planner remain unchanged.

**Tech Stack:** TypeScript, WXML/WXSS/WXS, small original SVG icons; no dependencies/backend/paid map styles.

**Spec:** `docs/superpowers/specs/2026-11-13-glass-map-design.md`

## Global Constraints

- Preserve current static data, eligibility, routing limits and stale camera/GPS guards.
- No per-move JS bridge updates; transform transitions only, no large animated blur.
- Three bounded sheet positions, actual visible scroll area, safe bottom/copyright gap and unobscured map fitting.
- No unconfirmed preset endpoints, no automatic GPS request, no unsafe failed-location fallback.
- FormalAppID and raw screenshots/records stay local; no public release or automatic next-PR merge.

## Review Focus

- Return-to-same-snap, gesture cancel and programmatic changes must reset the visible transform.
- Search keyboard and sheet changes must not leave unreachable controls or trigger hidden map taps.
- Newly selected journeys/endpoints cannot be overwritten by stale sheet/fit/location callbacks.
- Missing/invalid device dimensions have finite usable geometry.
- Plans need two confirmed endpoints; location failure must not invent a default boarding stop.
