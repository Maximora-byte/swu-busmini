# Release hardening implementation plan

**Goal:** 小范围补全可恢复错误处理、端点状态转换与官方包体回执门禁，验证后发布新候选。
**Architecture:** 独立错误恢复模块；兼容现有平面绑定的端点模型；真实构建大小证据与输入指纹检查。
**Tech Stack:** TypeScript、微信小程序WXML/WXSS、node:test、官方开发工具CLI、GitHub Actions。
**Spec:** ../specs/2026-11-14-release-hardening-design.md

## Global constraints
- 不全面重写、不引入事件总线、不改原始数据、隔离门禁或已有规划语义。
- 错误处理不输出／持久化原始异常、用户坐标、查询或凭证。
- 包体以官方构建回执为准；512KiB是项目内部预算，不冒称平台限制。
- CI校验构建证据的输入指纹与预算，不要求微信登录密钥，也不冒称独立官方编译。
- 发布前脱敏，体验／审核状态按官方回执或用户明确确认区分。

## Tasks
- [x] 错误兜底：先失败测试，再实现白名单错误类别、恢复页、全局钩子、循环与导航失败保护。
- [x] 端点状态：先回归测试，再抽取公共状态及转换；保留起点不对称语义与界面接口。
- [x] 实际包体：验证官方preview回执；实现指纹、预算、过期／畸形回执测试及CI门禁。
- [x] 集成：运行数据同步、数据校验、类型与完整覆盖率，开发工具异常／规划回归，独立审查。
- [ ] 发布：真实预览产物与脱敏证据，PR与CI核验后合并，上传新开发版本并记录体验版确认边界。
