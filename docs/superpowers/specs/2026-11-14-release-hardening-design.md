# 小范围发布加固

用户明确授权：补全错误兜底、整理端点状态、增加实际包体检查；使用多个agent，测试通过后提交并合并PR、脱敏上传新体验候选。保持现有地图、站点、方向与规划行为，不全面重写。

## 实现选择

- 错误兜底采用独立轻量恢复页及App错误钩子，能从异常／未找到页面回到固定首页；合并重复恢复，避免恢复页自身错误引起循环。只保留白名单错误类别，不记录原始异常、坐标、搜索词、令牌或路径，不增加遥测服务。
- 端点整理采用公共模型、纯状态转换及平面视图适配，保留现有WXML/API和原始站点身份，不引入事件总线。来源仍为单一页面状态，避免两份可变状态不同步。起点定位、失败回退、未确认输入、方向约束、交换与过期请求语义保留。
- 实际包体依据官方开发工具preview的info-output回执，发布前记录脱敏大小、输入指纹与构建配置；CI核验指纹未过期及项目内部512KiB预算。原始目录大小不替代官方产物体积。CI在无微信凭证时验证已生成的构建证据，不冒充独立官方编译或签名认证。若预览回执不足以提供大小，先明确能力边界，不用合成数字通过发布门禁。

## 并行边界

- 错误agent负责app、恢复页、错误服务与相关测试，不改journey页面。
- 端点agent负责端点服务、journey逻辑和journey测试，不改app或CI。
- 包体agent负责构建检查脚本、策略、CI及脚本测试，不改小程序运行时代码。
- 主agent负责集成、最终候选、独立审查、实际预览与上传回执、脱敏和PR操作。

不新增用户信息采集、外部密钥、付费地图调用、原始坐标审核或轨迹改写。真实手机及微信审核状态按实际证据记录；已有微信后台站点安全限制不得通过更换工具绕过。
