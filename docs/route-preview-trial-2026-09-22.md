# 彩色路网自动获取试验（2026-09-22）

按用户要求对 1～9 路尝试腾讯地理编码及驾车路段生成。仅开发时请求，用户打开小程序不会实时请求路线 API。

## 结果和保留问题

- 20 个已有线路参考点查询，54 次实际请求（20 次地理编码、34 次有方向驾车请求）；共享路段命中缓存。
- 16 个候选通过坐标范围、相似度及完全重复坐标过滤。这只是可供检查的候选，不是人工确认。
- 62 个带线路/方向关联的实验片段，全部 `needs_review`；共享片段会被不同线路引用。
- 二号门、圆顶、五号门、二食堂返回完全相同的 GCJ-02 坐标：29.826298,106.429286，无法区分其真实地点，因此全部拒绝参与预览。
- 驾车接口可能绕行校外道路、不遵循校园车的通行规则；其余候选也可能只命中建筑/地名而非候车位置，不能认为片段已与校车路线吻合。

## 与 2025 校园图片的关系

沿用图片 1～9 路的站序和颜色。不把这张示意图当作经过地理配准的影像，不叠放拉伸到腾讯底图，也不从像素反算坐标。图片与实际道路的精确重合仍需可靠的现场坐标和真实乘车轨迹。

## 查看和审核

1. 打开校园地图，主动开启“实验预览”。橙色提示说明尚未审核，虚线显示可用片段，缺失段留空。
2. 可查看全部线路，或关闭“全部线路”单独选择一条；用“看全线”调整视野。
3. 对照当前站牌、具体候车点及真实乘车路线复核。不得仅因腾讯成功返回或视觉相似就批准。
4. 正式数据沿用既有 CoordinateReview / RouteGeometry 审核流程。本次没有修改正式站点坐标、线路关系或已验证轨迹。

数据保存在 `miniprogram/data/route-preview.json`，含查询词、候选、警告及独立路段；不含密钥。内部调用缓存不推送 GitHub。
