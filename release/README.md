# Official package-size evidence

`npm run check:package-size` checks `release/package-size.json` against the staged/tracked runtime and public compilation configuration. It enforces our **internal 512 KiB budget**, not a claim about WeChat's platform limit. Runtime/compiler-input changes invalidate evidence; there is no calendar-based expiry for unchanged inputs. The policy lives in `package-size-policy.json`.

Size comes only from an actual official WeChat DevTools `preview --info-output <private JSON file>` or `upload --info-output <private JSON file>` receipt. Source-directory size is never accepted. Currently only a single main package is supported: the receipt must have `size.total` as a positive integer byte count and exactly one `size.packages` entry with `name: "TOTAL"` and the same size. Subpackages and plugin configurations fail closed until their receipt and budget semantics are implemented.

1. Stage all intended `miniprogram/` inputs and `project.config.json`. Keep private/ignored files outside `miniprogram/`; even ignored runtime files fail the gate.
2. Export those staged inputs to a private build project. Its public `project.config.json` may replace only top-level `appid`. All other public config is bound by the fingerprint; no `project.private.config.json` is allowed in the build project. Use the same compiler settings when running the official CLI, without build-setting overrides.
3. Run `npm run fingerprint:package-size` and retain the printed SHA-256 before the official build. Obtain the installed official DevTools version from trustworthy installed-version metadata (for example the executable ProductVersion); do not guess a version or treat help text as a version result.
4. Run the official authenticated preview/upload yourself, keeping receipt, QR, AppID, paths and CLI logs outside the repository. Preview's QR output must also be a private path (for example `--qr-format image --qr-output <private PNG file>`). Confirm CLI success and that the receipt was generated by this build. Exit code zero alone is insufficient: the CLI can report a network failure without producing a receipt. Use a fresh output path for every attempt; an absent receipt fails the gate.
5. Immediately record the real receipt using the command below. The recorder compares the actual private candidate runtime/config to the staged inputs and verifies the pre-build fingerprint before writing the sanitized evidence. A malformed receipt or unsupported size shape fails without producing evidence.

```text
npm run record:package-size -- --receipt <private info-output JSON> --project <private build project> --tool-version <actual dotted CLI version> --build-version <dotted candidate version> --input-sha256 <pre-build SHA-256> --operation preview
npm run check:package-size
```

For an actual upload receipt use `--operation upload`. Do not relabel upload as preview. The recorder does not invoke any authenticated tool. Do not use test fixtures as release evidence.

The evidence schema is enforced by `scripts/package-size.ts`: exactly schema version, official-operation source, UTC capture timestamp, numeric dotted DevTools/build versions, input SHA-256, whitelisted public compilation profile (single-main kind, compile type, library version and config hash), and the validated numeric size structure. Unknown evidence fields are rejected. The recorder copies no AppID, QR, local path, exception text or session data from the receipt. It stores evidence outside the runtime to avoid a fingerprint cycle. UTF-8 source text normalizes CRLF to LF; binary asset bytes are preserved.

CI needs no WeChat credentials. It verifies the recorded sizes, schema, timestamp, current input fingerprint and budget. It does **not** independently run the official compiler, authenticate the receipt, attest a signature, or prove real-device acceptance. The release operator is responsible for pairing the successful official build with the exact candidate, version, pre-build fingerprint and freshly generated receipt. If the official receipt does not supply supported package sizes, the release gate remains failed; do not substitute source size or synthetic numbers.
